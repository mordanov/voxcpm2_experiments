Welcome to our presentation for the Microsoft Fabric Hackathon. Today, we are excited to walk you through our solution: the ProofWeave Modernization Factory, and the end-to-end Proof of Concept we built to bring it to life. Every enterprise modernization initiative faces the same fundamental crisis of trust: critical business data is scattered across multiple aging systems, business rules are buried in legacy code and spreadsheets, and leadership no longer trusts the numbers on their dashboards. Our mission was clear: build an AI-powered modernization pipeline that consolidates five fragmented legacy sources into a unified analytics platform, and mathematically proves that nothing got lost along the way.
----
Before diving into our implementation, let us look at how our Proof of Concept builds upon our architectural blueprint, ProofWeave version four. The blueprint establishes three core phases: Understand and Approve, Generate and Execute, and Reconcile and Publish. Its central architectural rule is that the Source-to-Target Mapping, or S-T-T-M, acts as a formal review contract and execution input, never as unchecked AI text. In our Proof of Concept, we took this blueprint and operationalized it into a concrete ten-step Medallion architecture across Bronze, Silver, and Gold layers. Throughout the entire pipeline, we enforce a strict division of labor: Azure OpenAI handles semantic discovery, ambiguity resolution, and code synthesis, while deterministic code and human review gates enforce validation, execution, and parity checks.
----
To test our modernization factory against realistic enterprise complexity, we needed five legacy systems with messy, overlapping data. Because raw legacy systems were not provided for the challenge, we engineered a custom data generator based on Microsoft's World Wide Importers database. We transformed column names, identifiers, and customer records, and split the data across five partially overlapping systems following the fictitious merger-and-acquisition timeline of a company called Harvest and Hearth Foods. Using Bicep Infrastructure-as-Code scripts, we deployed this entire legacy estate into an Azure resource group in the France Central region. First, we deployed Azure Cosmos DB for NoSQL to host the Web Shop database, where each online consumer or business order lives as a JSON document, and registered business orders are forwarded to the US ERP. Second, we deployed Azure SQL Database running SQL Server as ERP-US, the core wholesale system of record using English PascalCase schemas. Third, we deployed Azure Database for PostgreSQL Flexible Server as ERP-EU, representing an acquired German subsidiary with German snake-case tables, euro denominations, independent customer numbering, and intercompany stock purchases from the US parent. Finally, we deployed an Azure Data Lake Storage Gen2 account with two containers: a CRM container holding Dataverse-style CSV and JSON exports where prospects sit right next to active customers, and a Files container holding finance and operations Excel workbooks for euro-to-dollar exchange rates, sales targets, partial product cross-references, and Parquet files with cold-chain temperature readings.
----
With our five legacy sources live in Azure, let us examine the end-to-end system architecture of our ten-step pipeline. As shown in our architecture diagram, the workflow progresses through Bronze, Silver, and Gold layers using three distinct building blocks. The orange stages represent hybrid steps where deterministic code and the Large Language Model collaborate. The blue stages represent purely deterministic code operations, such as statistical profiling and semantic model publication. Crucially, the yellow hexagons represent mandatory verification and human review gates: the Row-Count Check in Bronze, the Spec Review and Failure Review in Silver, and the KPI Review in Gold. No data or generated code can advance to the next tier without passing these gates.
----
The pipeline begins in the Bronze layer with Steps One and Two. In Step One, Ingest, deterministic ingestion code connects to Cosmos DB, Azure SQL, PostgreSQL, and Data Lake Storage to copy and load the raw extracts into Bronze. At the same time, we deploy our first Azure AI component: the LLM reads complex, irregular Excel file layouts in the Files container to automatically identify headers, multi-table sheets, and structural boundaries without manual parser coding. Immediately after ingestion, the pipeline hits its first automated gate: a strict Row-Count Check that verifies Bronze record counts against the source systems. Once verified, Step Two, Profile, runs purely in deterministic code to calculate column statistics, null distributions, data types, and value patterns across all five sources. This statistical profile gives the AI rich metadata context in later steps without overwhelming prompts with raw table rows.
----
Moving into the Silver layer, Steps Three and Four tackle schema unification and cross-system entity resolution. In Step Three, Model, the LLM analyzes the Bronze statistical profiles and proposes a unified Silver specification—our Source-to-Target Mapping—harmonizing English PascalCase tables from the US ERP, German snake-case tables from the European ERP, JSON documents from the Web Shop, and CRM exports. Deterministic code immediately validates this specification for schema completeness and structural integrity, and then pauses at the Spec Review hexagon so a human architect can inspect and approve the mapping contract. Once approved, Step Four, Match, solves one of the hardest problems in post-merger data integration: duplicate entities across systems with different numbering and languages. Deterministic code first runs high-speed similarity scoring and graph clustering across customers and products, and then calls the LLM specifically to adjudicate unclear, borderline pairs—such as matching a German subsidiary account or a CRM prospect to a US wholesale customer.
----
Once entities are matched, Steps Five and Six build and verify the conformed Silver tables. In Step Five, Build, deterministic code generates canonical surrogate keys and materializes the cross-system lookup tables, while the LLM writes the complex SQL transformations required to populate each Silver table according to the approved specification. A standout operational highlight here is our automated self-healing repair loop: if a generated SQL query encounters a syntax, type, or runtime error during execution, the pipeline captures the exact database diagnostic and feeds it back to the LLM to repair the SQL automatically. In Step Six, Verify, we apply a two-tiered quality shield. Deterministic code runs standard relational checks on primary keys, foreign keys, nulls, and duplicate-free reruns. Meanwhile, the LLM generates domain-specific extra checks—for example, verifying that business webshop orders forwarded to ERP-US are not double-counted, and that intercompany stock purchases between Germany and the US reconcile properly. Any discrepancy routes directly to the Failure Review gate, blocking bad data from ever reaching Gold.
----
After Silver passes verification, the pipeline enters the Gold layer across Steps Seven through Ten to deliver business-ready analytics. In Step Seven, Publish, deterministic code automatically generates and publishes the base Semantic Model over our conformed tables. Next, we execute an automated KPI factory. In Step Eight, KPI Define, the LLM researches the unified data model and business context to propose high-value executive KPIs and their formal specifications—covering core business metrics such as Total Sales, Active Customers, Average Discount, and logistics cold-chain compliance. Deterministic code validates the KPI spec, and a human reviewer signs off at the KPI Review gate. In Step Nine, KPI Build, the LLM generates the analytical SQL to materialize the Gold KPI tables, while deterministic code executes the queries and runs reconciliation checks against expected control totals. Finally, in Step Ten, KPI Publish, deterministic code injects the verified DAX measures directly into the semantic model, making it immediately available for Power BI reporting.
----
To wrap up, let us highlight the operational qualities that make our solution enterprise-ready. First, we never treat AI as an autonomous black box; every AI output is constrained by deterministic code validation and explicit human sign-off gates, turning the blueprint's governance vision into working software. Second, our hybrid architecture is both cost-effective and scalable: heavy data movement, statistical profiling, similarity clustering, and key generation are handled by fast, deterministic code, while Azure OpenAI is invoked surgically where semantic reasoning adds the highest value—reading messy spreadsheets, bridging German and English schemas, resolving ambiguous entity pairs, self-repairing SQL, and authoring domain checks. Combined with our fully reproducible Bicep deployment in Azure, our solution proves that you can modernize fragmented legacy estates in a fraction of the time while guaranteeing complete trust in every number.
